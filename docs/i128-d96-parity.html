Summary

Arithmetic: no incorrect result was found. An independent BigInt-oracle harness, a fresh-context code review, and the existing suites all agree with the implementation on every case tried, in debug and release builds.

Speed: at 8 and 10 dp, mul and div run at 0.31–0.56× the fixdec D96 time. At 12 dp, mul is 0.96–0.99× and div about 1.01× D96 (worst single cell 1.069×), inside the 10% target. Against the pre-change baseline, 12 dp div is 35–40% faster and 12 dp mul 10–14% faster.

Qualification: the timings were taken on a shared, busy machine with no CPU pinning, and 57 of the 144 compared cells are flagged noisy. The target is observed, not qualified. Do not read this as proof of parity.

What changed

Results and error behaviour are unchanged: same overflow and divide-by-zero outcomes, same five rounding modes, same full i128 range. Only the way the answer is reached changed.

Correctness evidence

Independent differential harness

tests/arith_adversarial.rs checks the public API against a BigInt specification written from the definition of each rounding mode, with no code shared with the library. Operands are steered at the thresholds where an implementation switches path: 263, 264, 2126, 2127, 2128, powers of ten, results exactly at and one past the type limits, and exact half-way ties.

  • checked_mul_ext / checked_div_ext: every scale difference in [−DIGITS, DIGITS] for the sampled cases, all five rounding modes, i16 to i128 and u16 to u128, same-width and mixed-width operands (the magnitude path), and ConstScaleFpdec at 8, 10, 12 and 18 dp.
  • calc_mul_div, rounding_div, integer division, ratio multiplication, round-to-multiple, %, add, sub, round_diff_ext, checked_neg, checked_abs.
  • Result: zero mismatches across 8 seeds in release at 40× scale (and 1× and 10× runs), plus debug runs (which also catch arithmetic-overflow panics inside the fast paths).

The harness was shown to be able to fail. Each of these planted bugs made it fail: dropping the carry in checked_mul_u128; removing the Floor/Ceiling swap for negative results; widening the 63-bit guard to 64 bits; changing the -2127 limit check by one; removing the sign swap in round-to-multiple; making the TowardsZero shortcut round up.

Fresh-context review

A separate reviewer was given only the diff and the correctness contract, not the author's conclusions. It ran its own oracle (about 57 million calc_mul_div cases, the mul/div paths for both 128-bit types over all 77 scale differences, 29 mixed-type pairs, out-of-range scales) with overflow checks enabled, and checked by hand that every call into unchecked_div_single_r1b has its numerator bound. It found no defect; its one finding was the stale SAFETY comment, now fixed.

A weak regression test, corrected

The u64 test for the rounding-extra overflow used 3e9 × 3e9. Each operand has 32 leading zeros, one short of the 65 the fast-path guard needs, so it never entered the path it claimed to cover. It now uses u32::MAX × i32::MAX at 19 digits, which does.

Performance

Method

Matched, same-rounding (TowardsZero) comparison of the current tree, the baseline 3f6e82a, and fixdec D96 (a853c0c), at 8, 10 and 12 dp, for add, sub, mul and div. Six workloads (small values, USD amounts, rates; each positive-only and mixed-sign), 1,024 shared exact 6 dp input pairs per cell, 7 rounds, at least 10 ms per cell, medians, ratios paired within each round. Every result is validated exactly against Decimal before timing. Release profile, no LTO, codegen-units = 1, macOS ARM64.

Noise. CPU placement and frequency were not controlled. The host was running about two dozen other CPU-using processes (build servers, editors, other agents), load average 6–7. A cell is flagged noisy when its full-range spread exceeds 20% or MAD/median exceeds 5%; no sample was discarded. 57 of the 144 compared cells are flagged. The runner therefore marks the run diagnostic-unpinned-shared-host and parity_passed: false by design.

Limits and what was not checked

  • Scale differences outside [−DIGITS, DIGITS] return None even when a representable result exists (for example 1 × 1 at a difference of 39 would round to 0 or 1). This is the documented contract of checked_mul_ext / checked_div_ext, unchanged here.
  • Sampling, not proof. The harness and the reviewer's oracle cover millions of boundary-steered cases, not all 2256 operand pairs. The bound arguments for each fast path are written next to the code and were re-derived by the reviewer.
  • Platforms and builds. Tested on one macOS ARM64 host, debug and release without LTO. Not tested: 32-bit targets, LTO or other codegen settings, the pyo3 feature, the fuzz/ targets, Miri.
  • Performance qualification. A quiet, pinned machine is needed to turn “target observed” into “parity qualified”. The numbers above are diagnostics.
  • Code size. #[inline(always)] on the public out-of-band checked_mul_ext / checked_div_ext copies their bodies into every call site.
